# KTT 6Terusan 车间运营驾驶舱 · 前端 Demo

面向老板的维修车间数字化看板 Demo。数据全部 mock，但**所有指标由结构化事件数据推导**（口径对齐方案文档 6.3），不是写死的数字。

## 运行

```bash
npm install
npm run dev        # http://localhost:5173
npm run build      # 产物在 dist/
```

## 页面（6 个）

| 路由 | 页面 | 回答老板的问题 |
|---|---|---|
| `/#/` | 老板驾驶舱 | 今天怎么样？承诺交车有没有风险？哪里卡？为什么？ |
| `/#/floor` | 车间实时看板 | 五个工位此刻谁在干、谁在等、谁空着；还能接几台 |
| `/#/vehicles` | 在场车辆进度 | 每辆车修到哪了、ETA vs 承诺（按交付风险排序） |
| `/#/vehicle/:id` | 车辆时间线 | 这辆车到底经历了什么（含证据链） |
| `/#/delays` | 延误与根因 | 为什么慢、谁的责任；复核抽屉（确认/改判/驳回留痕） |
| `/#/analytics` | 运营分析 | 趋势、A/B 班组对比、工位热力、任务类型效率 |

右上角可切换 **中/EN**、进入全屏（大屏演示模式）。

## 数据层

```
src/mock/data.ts      # 事件底座：Visit/BaySession/WorkSegment/DelayCase/EvidenceRef
                      # 固定随机种子；今日剧本：喷漆超时、刹车片缺货、B班巡检空窗、低置信车牌
src/derive/metrics.ts # 指标推导：中位/P90 周转、占用率、有效作业率、等待损失(¥600/h)、
                      # 交付承诺 ETA、根因分布、TAT 直方图；环比按"昨日同一时刻切面"计算
```

## 口径说明

- 进度条 = 已用工时 / 目标工时（>100% 变红）；等待时进度停住、ETA 继续走
- 等待损失 = 等待时长 × ¥600/h（价值系数 mock，正式版由财务/运营定义）
- 工单金额为文档外 mock 扩展字段；返修率未纳入（文档未覆盖）
- 人员数据只做班组级对比，不做个人排名（方案治理边界）
